# CORE v11.2.1

Date: 2026-07-30

## Summary

Patch release. Fixes a release-verifier defect that let missing validator
scripts and missing input fixtures report as `passed` instead of
`pending_runtime`. No public schema, contract or CLI surface changed.

## Fixed

- `scripts/verify_release.py` `_same_result` treated any reproducible
  non-zero exit as `passed`, including a crash caused by a missing script,
  module or `.json` input fixture. This silently reported unimplemented or
  incomplete checks as green and bypassed the `allow_missing_surface` guard
  that call sites already declared. It now classifies a missing runtime
  surface as `pending_runtime`.
- Added `_missing_input_fixtures()`, a structural pre-check (fixture path
  existence) used by both `_same_result` and `_same_output`, so a missing
  `.json` fixture argument is caught before the subprocess runs at all,
  independent of each script's own error-message wording.
- Added a `checks_summary` block (`declared_count`, `executed_count`,
  `by_status`) to the `full`, `tooling` and `release-metadata`
  release-verification payloads.
- Hardened `_missing_input_fixtures` against a mirror-image regression:
  arguments following an output flag are skipped, so a not-yet-created
  output path can never be misread as a missing input fixture.
- Repointed the CI release gate from v11.1.0 to v11.2.1. Both of its
  frozen-manifest steps were failing on a green tree by re-verifying
  v11.1's historical byte inventory against the current tree.
- Documented the frozen-manifest lifecycle in `VERSIONING_POLICY.md` so the
  next release line does not repeat either mistake.
- Rescoped the two v11.1 baseline tests from release-time byte-equality
  gates into historical-baseline integrity tests. They asserted the live
  tree stays byte-identical to the v11.1 snapshot, true only at the instant
  v11.1 was cut: 19 of 138 tracked artifacts have legitimately changed
  since, and a third assertion demanded `schemas/core/` still hold exactly
  26 files when it now holds 29. Both were therefore already failing at the
  v11.2.0 tag, before this patch. They now assert the durable properties
  instead (profile identity, exact inventory and roles, canonical order,
  uniqueness, `artifact_count`, self-consistent fingerprint, continued
  existence of every frozen artifact, builder determinism and inventory
  shape). The v11.1 manifest is not rewritten, matching the
  `historical_baseline_preserved` policy `verify_release.py` already
  applies to it, and forgery detection is untouched.
- `scripts/check_public_surface.py` gained an explicit, per-line
  `# privacy-guard:allow` opt-out for lines that legitimately quote a
  forbidden term to assert its absence, rather than leak it. Found while
  running the guard before this release: `tests/test_contract_program_runtime.py`'s
  own negative test for private-vocabulary leakage tripped the guard on
  itself, unchanged since before v11.2.0 and already present in that
  published tag. Confirmed the marker does not suppress genuine hits before
  applying it.

## Validation

- `python scripts/verify_release.py --skip-full-pytest`: `checks_summary`
  moved from 148 `passed` (49 of them vacuous — script/fixture absent) to
  92 genuine `passed` and 78 honestly labelled `pending_runtime`.
- `python -m pytest tests/ -k 'verify_release or release_manifest' -q`
  passed after the v11.2.1 manifests were rebuilt.

## Notes

No schema, validator CLI contract or public contract surface changed; this
is a PATCH per [`VERSIONING_POLICY.md`](../VERSIONING_POLICY.md#semantic-versioning).
The release manifest is frozen locally with an exact SHA-256 inventory. This
repository state does not authorize deployment, network submission,
anchoring or DSK promotion.
