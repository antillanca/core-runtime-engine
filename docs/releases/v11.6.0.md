# CORE v11.6.0 — Stabilization Before CORE-Interop

Date: 2026-09-07

Status: release candidate until the local gate, immutable tag and controlled
package publication have all completed.

## Summary

- Fail-closed deterministic validation for DSK, classification and audit data.
- Replay certification is required for the v11.6.0 release gate.
- The replay gate now executes both frozen reference datasets and the offline
  Expert Router fixture; both are validation-only and cannot authorize
  providers, commands or publication.
- Package CLI exposes `core-runtime --version`.
- The v11.5.1 frozen manifest remains historical; v11.6.0 has its own v9
  manifest and validator.
- DSK means **Domain Scale Kernel**; the technical compatibility identifier
  remains `core.dsk.v3`.

## Validation

- `core-runtime --version` returns `11.6.0` after installation.
- `python scripts/validate_frozen_release_manifest_v11_6.py ... --verify-live-artifacts`
- `python scripts/verify_release.py --target v11.6.0`
- `python -m pytest -q`
- `python scripts/verify_release.py --target v11.6.0 --group replay`
- `python scripts/replay_certification.py --reference-dir tests/reference_data --output replay-report.json`
- `python scripts/certify_router_replay.py --all`
- `python -m build` followed by `twine check dist/*`.

## Notes

This release does not rename `core.dsk.v3` or change v11 fingerprint semantics.
The breaking canonicalization, strict-I-JSON and envelope migration is
documented for v12.0.0 in `docs/VERSIONING_POLICY.md` and must not be enabled
implicitly by this line.
