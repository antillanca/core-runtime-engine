# CORE v11.1.0

## Summary

Adds a generic, deterministic, and non-custodial frozen-rule anchoring path.
General rules can be published as complete replayable artifacts. Personal
rules remain off-chain and are represented by randomized blinded commitments.
External wallet approvals are cryptographically verified, collected into a
domain-separated SHA-256 Merkle batch, and prepared as an unsigned transaction
for the minimal `CoreRuleAnchor` contract. Contract creation is also emitted
as a reproducible, independently validated unsigned deployment request.

CORE does not sign, broadcast, hold funds, auto-refill a wallet, issue a token,
or decide that a rule is true or beneficial. Blockchain records existence and
ordering only. The accountable operator retains the wallet and reviews every
state-changing transaction externally.

## Executable contract hardening

The public generic contract family now has a strict semantic evaluator in
addition to JSON Schema compatibility. The executability audit runs coherent
and schema-valid semantic-negative probes for every registered contract and
rejects any unclassified public schema.

`PhysicalSafetyAssuranceCase.v1` is the first contract born under the stricter
profile. It preserves observed extremes, treats out-of-distribution inputs as
unknown, requires independent physical barriers and adversarial tests, and
protects the affected person's right to understand, challenge and stop the
system. Its output never authorizes execution or deployment.

## Security corrections

- Deleted the legacy private-key argument and `ANCHOR_KEY` environment path.
- Deleted local transaction signing and transmission from CORE.
- Bound approvals to rule fingerprint, chain ID, and contract address.
- Enforced canonical low-s signatures and recovered signer authorization.
- Kept personal content hashes and random commitment openings off the public
  surface.
- Added exact calldata, event, state, chain, and confirmation verification.
- Replaced stale hardcoded chain allowlists with positive EIP-155 IDs plus
  explicit chain-adapter/RPC verification at the connected boundary.
- Fixed v11 release-gate ordering and restored executable Merkle checks that
  had previously appeared only as missing historical surfaces.

## Evidence and agency terminology

Evidence is modeled as a bounded projection and can originate from a human,
nonhuman biological source, software, human-directed software, or a mixed
ensemble. Accountable authorization remains a separate authorized-signer
boundary. Frozen historical `human_*` field names remain unchanged for replay
compatibility.

## Verification

```bash
python scripts/audit_contract_executability.py
python -m pytest -q
python scripts/verify_release.py --target v11.1.0
npx --yes solc@0.8.30 --bin --abi contracts/CoreRuleAnchor.sol
```

No production deployment address is part of this release. A deployment must
be compiled reproducibly, performed by an external wallet, and verified before
its public address is accepted by a real approval.
